## Evidence notes

### What is fully automated

- Rust owns the schema, validation, matching, attendance, hours, verification, reports and
  backup rules. The integration suites open a real temporary SQLite file, perform writes,
  reopen the database, and assert the persisted rows and audit trail.
- `random_small_cases_match_the_oracle` compares the flow solver with exhaustive search on
  generated small cases. `matches_the_brute_force_optimum_on_a_known_case` pins one case a
  judge can follow by hand.
- Frontend tests cover the repository command map, the preview fallback, selector
  consistency, Mission Control rendering, account creation, axe checks on all 43 routes, print
  gating, and route mounts.
- `pnpm verify` is the local gate: typecheck, lint, format, Vitest, web build, print audit,
  accessibility-tree audit, 200% zoom audit, Rust format, Clippy, and `cargo test`.
  `.github/workflows/ci.yml` runs the same frontend and Rust checks plus the native
  WebdriverIO suite on macOS for pushes and pull requests.

### What is a manual check, not a test

- A human VoiceOver or NVDA pass. The Chromium accessibility tree and control names are
  audited on all 43 routes, but announcement quality still needs a person.
- A physical camera scan at the kiosk. The QR payload and its validation are tested in Rust;
  venue lighting and camera permission are not.
- Windows and Linux native UI. The release workflow builds and attaches their installers,
  but the WebdriverIO suite runs on macOS only.
- Airplane-mode launch is a rehearsal step. The app has no runtime network requests, but the
  offline claim should still be demonstrated on the competition machine.

### Numbers to avoid overstating

- Role coverage and seat fill are deliberately different definitions. The dashboard labels
  both; do not describe the 91 % card as seat fill. See [METRICS.md](METRICS.md).
- Kiosk mode is an authenticated coordinator route in the same window, not a separately
  capability-scoped webview. The app does not claim kiosk-level OS isolation. See
  [SECURITY.md](SECURITY.md).
- The app is local and single-tenant. Accounts and roles are enforced in Rust, but there is
  no multi-user sync, server-side identity provider, or encryption at rest. The demo password
  is public until an operator changes it.
